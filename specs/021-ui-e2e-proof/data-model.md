# Data Model: UI E2E Proof

<!-- markdownlint-disable MD013 -->

## ProductHardeningEvidenceManifest

Stable JSON artifact used by 021-025 to map product claims to proof entries.

Fields:

- `version`: constant `hideout.product-hardening-evidence/v1`.
- `generatedAt`: RFC 3339 timestamp.
- `commit`: git commit identity for the proof run when available.
- `dirty`: whether the source tree had local changes when available.
- `packageIdentity`: optional installed/package identity for packaged runs.
- `proofs`: ordered list of `ProofEntry`.

Rules:

- The manifest is evidence, not product authority.
- The manifest must not contain raw control-plane secrets.
- A manifest with only `not-run` UI lanes cannot satisfy 021 completion.

## ProofEntry

One result for a browser, terminal, local-fast, real-gate, schema, docs, or
other product-hardening proof lane.

Fields:

- `proofId`: stable id, for example `021.webui.browser.console`.
- `featureId`: stable spec id, for example `021-ui-e2e-proof`.
- `mode`: `browser-e2e`, `pty-e2e`, `local-fast`, `real-gate`,
  `schema`, `docs`, or `unit`.
- `evidenceClass`: human-readable class such as `local-ui-e2e`.
- `status`: `passed`, `failed`, or `not-run`.
- `commandSummary`: redacted command summary, not a raw shell transcript.
- `coveredClaims`: list of `CoveredClaim`.
- `prerequisites`: list of `PrerequisiteStatus`.
- `artifacts`: list of `ArtifactRef`.
- `redactionStatus`: `passed`, `failed`, or `not-run`.
- `startedAt` / `endedAt`: optional RFC 3339 timestamps.
- `host`: optional host/platform summary.
- `notes`: optional bounded notes.

Rules:

- `not-run` entries must include at least one unavailable prerequisite or an
  explicit reason.
- `failed` entries must not mark covered claims as satisfied by downstream
  tooling.
- Artifact paths are relative to the evidence directory unless explicitly
  marked as external.

## CoveredClaim

Stable mapping from proof to product claim.

Fields:

- `claimId`: stable id such as `021.FR-004` or `docs.tui-webui.live-console`.
- `source`: `spec`, `docs`, `status`, `test-plan`, or `quickstart`.
- `description`: short claim text.
- `scope`: optional qualifier, such as `browser`, `tui`, or `local-ui`.

Rules:

- Claims must be specific enough that 025 can detect overclaim drift.
- A broad documentation section should map to multiple claims rather than one
  vague claim.

## ArtifactRef

Pointer to an evidence file generated by a proof run.

Fields:

- `kind`: `screenshot`, `terminal-capture`, `log`, `event-summary`,
  `request-summary`, `manifest`, `schema`, or `docs-report`.
- `path`: evidence-directory relative path.
- `sha256`: optional digest.
- `redactionStatus`: `passed`, `failed`, or `not-run`.
- `description`: short artifact purpose.

Rules:

- Artifacts containing raw terminal/browser/log data must pass redaction before
  being used as covered-claim evidence.
- Screenshots may be stored only when they do not expose hidden paths or tokens.

## BrowserProofResult

Structured summary for the WebUI browser lane.

Fields:

- `pageLoaded`: boolean.
- `panelsVisible`: list of visible panel ids or names.
- `eventUpdateObserved`: boolean.
- `actionRoundTrip`: `BrowserActionResult`.
- `authFailureObserved`: boolean.
- `hiddenPollingDetected`: boolean.
- `fixtureBoundary`: optional string when a fixture server is used.

Rules:

- `hiddenPollingDetected=true` makes the proof fail.
- Fixture-only browser proof cannot cover daemon transport claims.

## BrowserActionResult

Result of the required low-risk browser action.

Fields:

- `action`: constant `notice.ack` for v1 required proof.
- `requestObserved`: boolean.
- `payloadValidated`: boolean.
- `responseHandled`: boolean.
- `visibleStateChanged`: boolean.
- `authMode`: `valid-token`, `wrong-token`, or `expired-token`.

Rules:

- Required passing proof needs valid-token success and a separate wrong or
  missing token refusal check.

## TerminalProofResult

Structured summary for the TUI terminal lane.

Fields:

- `processLaunched`: boolean.
- `harness`: `pty`, `terminal-process`, or `pipe-compatible`.
- `sectionsVisible`: list of visible terminal sections.
- `eventUpdateObserved`: boolean.
- `fallbackObserved`: boolean.
- `hiddenPollingDetected`: boolean.
- `eventSource`: `real-daemon` or `deterministic-seam`.

Rules:

- Render-only proof is not a valid terminal proof.
- `hiddenPollingDetected=true` makes the proof fail.

## PrerequisiteStatus

Dependency status for a proof lane.

Fields:

- `name`: prerequisite name, such as `browser`, `playwright`, `pty`, or
  `daemon`.
- `status`: `available`, `missing`, or `skipped`.
- `reason`: optional detail.

Rules:

- Missing required prerequisites produce `not-run` evidence, not pass.
- Skipped prerequisites must explain whether the lane was optional for the
  current command or required for 021 completion.
