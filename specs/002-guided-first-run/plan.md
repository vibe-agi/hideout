# Implementation Plan: Tool Model Cleanup

**Branch**: `002-guided-first-run` | **Date**: 2026-07-06 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/002-guided-first-run/spec.md`

## Summary

Remove the old npm/provider/preset tool-supply model from Hideout and replace
it with diagnostic expected-command declarations. This plan aligns the current
implementation with the mediation-first architecture: Hideout may record and
diagnose which guest commands an operator expects to exist, but it must not
install, provision, download, or materialize those commands.

The cleanup is intentionally full-scope because Hideout is not released:
schema/profile/API/CLI compatibility for the old model is removed instead of
kept as legacy behavior. Old inputs fail closed with explicit migration
diagnostics. Valid `tools.expectedCommands` declarations become the only
generic tool-readiness model in this slice.

Out of scope for this plan: guided first-run onboarding, global/named
environment creation, base-image selection UX, daemon mode, TUI/WebUI
observation, public ecosystem trust, marketplace recipes, package-manager
installation, and product-specific agent support.

## Technical Context

**Language/Version**: Go 1.25.0 plus existing POSIX shell test/gate scripts.

**Primary Dependencies**: Standard library CLI/runtime, existing Manager,
profile, app, schema, and validation packages. Existing project dependencies
remain unchanged; this feature must not add package-manager integrations or
installer libraries.

**Storage**: Local Hideout store under `HIDEOUT_STORE_ROOT` or default store;
profile JSON/schema state; existing session/audit/environment stores only as
needed for diagnostics. No new tool artifact cache or installer state is
introduced.

**Testing**: `go test ./...`, targeted app/profile/schema tests, repository
scans for removed npm/provider/preset product surfaces, and `scripts/test-gate0.sh`.
No real Lima gate is required for this cleanup unless implementation touches
backend execution.

**Target Platform**: Host-side CLI/profile/schema behavior across supported
operator platforms. Runtime command existence diagnostics may report
environment-specific status, but materialization remains out of scope.

**Project Type**: Local privacy-runner CLI with Manager Core, typed profile
state, schemas, app command parsing, and documentation/spec artifacts.

**Performance Goals**: Tool diagnostics and profile validation must remain
cheap local operations; removing the old model must not add backend startup or
network activity to validation.

**Constraints**: Must not introduce arbitrary host execution, raw profile
writers, package-manager execution, guest setup scripts, product-specific tool
recipes, or compatibility shims that silently accept old installer fields.
Expected-command declarations are diagnostic state only.

**Scale/Scope**: One cleanup slice across profile/schema/app/docs/tests. It
handles existing local old fields by rejection with diagnostics, not migration.

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

- **Privacy Boundary**: PASS. The cleanup removes an installer/provider path
  rather than adding authority. Old fields fail closed. Expected commands
  record operator intent and diagnostic facts only.
- **Typed Authority**: PASS. Go owns profile/schema validation and diagnostic
  facts. No JS/config or provider gains execution authority. No package manager
  becomes Core semantics.
- **Workspace And Policy**: PASS. This feature does not broaden workspace,
  HostFS, mount, network, or host app authority.
- **Generality And Provider Scope**: PASS. The plan removes npm/preset/provider
  product semantics and replaces them with product-neutral expected-command
  declarations.
- **Evidence And Redaction**: PASS. Diagnostics must label states as expected,
  present, missing, not checkable, or unsupported old field. They must not
  claim installation or repair.
- **Backend And Distribution**: PASS. No backend materialization, helper
  installation, package downloads, or distribution changes are required.
- **Gates**: PASS. Gate 0 and package/schema tests are sufficient unless code
  changes unexpectedly touch backend/network/product isolation paths.
- **Status And Docs**: PASS. `docs/STATUS.md`, public READMEs/spec artifacts,
  and any docs mentioning tool setup must align with the diagnostic-only model.

**Pre-design result**: PASS. No constitution violation or complexity exception
is required.
