# Deferred Debt Ledger

<!-- markdownlint-disable MD013 -->

This ledger is the single place where intentionally deferred work with a real
trigger condition is recorded. It exists so that a deferral decided inside one
spec review does not silently disappear when that spec closes.

Rules:

- Every feature's `speckit` converge/analyze step MUST check that new deferred
  items from that slice are recorded here before the slice is marked done.
- Each entry names the condition that makes it due. When the trigger becomes
  true, the entry blocks the triggering work until resolved or explicitly
  re-deferred with a new trigger.
- Entries are removed only by a commit that implements them or a recorded
  decision that retires them. Do not delete entries silently.
- Non-claims (honest statements of what Hideout does not do) are not debt and
  do not belong here; they live in the threat model.

| `--rm` on the lima daemon needs a full disposable-teardown transaction, not a shallow `PreserveInstance=false` + `store.Remove` wiring. Semantics (from `privacy-run-design.md`, "cleanup over speed for a higher-risk command"): `--rm` = a **dedicated, disposable** environment (its own VM, `ModeDedicated`, `Active`) disposed after the run — distinct from the shared default (persistent) and `--ephemeral` (shared VM, session-local identity, now resolved). It is currently record-less (`Active=false`), so it fails on the daemon streaming path exactly like `--ephemeral` did (`SessionIsolationRequired=false` → `RunWithStreams` rejects), and its record-removal path (`FinishRunEnvironment` `run_environment.go:274`) is **dead code** (all `selectedRunEnvironment` callers pass `removeAfterRun=false`). Correct design (verified against code + a 2026-07-21 codex review): **(1) Resolution** — create a dedicated disposable env (unique per-run name; `ModeDedicated`; `Active`; `PreserveInstance=false`; `RemoveAfterRun=true`); set `InstanceName` from the new env id (`Store.Create` does not); re-include it in the runtime-disk provenance precheck (currently skipped for `RemoveAfterRun`); add a persistent `Record.Disposable` field (`environment.go` `Record` has none) so a restarted daemon can tell disposable from normal dedicated. **(2) Teardown is NOT `FinishRunEnvironment`** — an `Active` env's production teardown is `finishConcurrentRunEnvironment` (`run_apply.go:427` routes `Active` there), which today **unconditionally `store.Save()`s** the record and **deliberately retains** the environment network gateway (`run_environment.go:349-352`) and the lifecycle registration/incarnation. A correct `--rm` needs a daemon/lifecycle-governed disposable transaction: VM delete (`PreserveInstance=false` → lima Cleanup `limactl delete -f`, `lima.go:740`), record removal, network gateway close (today only on explicit stop/clean, `daemon/lifecycle.go`), and lifecycle journal/coordinator incarnation teardown. **(3) Graded failure handling** (not dispose-always: `limactl delete -f` failure lands in `cleanupErr`, `lima.go:741`) — target command non-zero → still dispose; session/HostFS cleanup errored but VM proved absent → remove record + return the cleanup error; delete failed or VM state unprovable → retain the disposable record with error for reconcile/clean (never fake unproved cleanup as success, `run_environment.go:299`). **(4) Crash-orphan GC must be provable**, not mark-and-delete (`daemon.go:330` reports-but-never-destroys unproven-ownership resources): `Disposable=true` is user pre-authorization, but GC still must prove no live owner, guest session terminated, instance identity matches, exact instance deleted/absent, gateway/runtime/journal cleared. **(5) Result** — keep `environmentId`/`environmentName` for audit, add an explicit disposition (`removed` / `cleanup-required`); resume hint already suppressed for `PreserveInstance=false` (`app.go:2038`). | Reconcile session-runtime scrub vs run establishment race (GROUP 3, #10). `BeginRunSession` exposes the environment session runtime before `AcquireOwner` writes durable owner evidence; startup/retry reconciliation can therefore classify it as an ownerless orphan and call `ClearSessionRuntime`. **Rejected fix:** making reconcile wait on `LockContext(env.ID)` while the current run holds that transition lock and waits in `BeginAttach` for reconciliation creates the lock cycle `run: transition lock → reconciliation`, `reconcile: reconciliation fence → transition lock`. **Required protocol:** allocate the session ID without exposing environment runtime, then obtain a coordinator-owned attach-establishment reservation before taking the transition lock. The reservation waits for any existing reconciliation, blocks new reconciliation/destructive mutation, and has explicit abort/timeout behavior. Only after that reservation succeeds may run acquire `LockContext`, re-read the record, create session runtime, write the owner record, and promote the reservation to the normal lifecycle registration. On failure it removes only its own runtime and releases the reservation; after a daemon crash the in-memory reservation disappears and the next reconciliation may prove and scrub any residue. Reconcile remains lock-free with respect to the transition lock, and no code may wait for reconciliation while holding that lock. Verification must force both interleavings (reconcile first and run reservation first), cancellation at each establishment stage, and daemon crash before/after owner durability. The protocol's safety invariants are model-checked ahead of implementation by `formal/AttachReservation.tla` (Gate 0), whose state space covers both interleavings, per-stage cancellation, and crash before/after owner durability; removing the reservation/reconcile exclusion reproduces the scrub race in TLC. The model does not replace the required Go interleaving tests when the protocol lands. | Before relying on daemon reconcile concurrency safety under startup/restart with in-flight runs; narrow/low-frequency today | 2026-07-21 GROUP 3 evaluation; corrected 2026-07-22 after lock-order review |
