# Hideout Implementation Status

<!-- markdownlint-disable MD013 -->

Status source for the current product surface. Detailed contracts remain in the
design documents; this file prevents implementation status from drifting across
many subsystem specs.

Current release state: private alpha / supervised dogfood with a latest local
release-candidate evidence bundle produced on macOS at commit
`5f3c0b7a4f0d`. Public GA still requires this evidence to be produced for the
final release artifact and explicit release-specific signoff.

Latest local release-candidate evidence: manifest at
`.hideout-release-evidence/release-dogfood-20260705T064523Z-5f3c0b7a4f0d/manifest.json`
(status passed, `scripts/test-phase1.sh --release-candidate`). A bundle
certifies only the exact commit recorded in its manifest; rerun
`scripts/test-release-dogfood.sh` on the release commit before cutting an
artifact.

MVP scope: a professional individual operator on their own machine; the
user-facing vocabulary is environments, workspaces, permissions, and audit.

## Implemented Product Paths

| Area | Status |
| --- | --- |
| Lima backend | Reusable environments, workspace mount, identity mounts, helper discovery, and command execution are implemented for the primary macOS dogfood path. Guest tools come from the declared base image or operator-run in-boundary setup; the guest boots from the environment's pinned base image declaration (template or digest-verified URL), and Lima does not run Hideout-owned package provisioning. |
| Lima real-run reference smoke | `scripts/test-lima-real-run.sh` and `scripts/test-phase1.sh --lima-real-run` provide a supervised reference workload over the real Lima backend: deterministic workspace artifact, guest-side success check, selected network evidence, fixed Boundary Action Set, and redacted audit/Boundary Summary checks. This is dogfood evidence for the reference slice, not unattended daily-use, GA, release-candidate, TUI/WebUI, or product-specific agent support. |
| Native backend | Implemented as a weak-isolation development harness only. It is not isolation evidence. |
| Alpha package lifecycle | Implemented. `scripts/package-local.sh` builds a release-like tarball with the `hideout` CLI, host shim, Linux guest shim, Linux HostFS daemon, Linux DNS stub, schemas, docs, installer, and artifact manifest. Packaged `install.sh` delegates to Go-owned `hideout package install`, which verifies checksums before copying, writes an installed-state manifest with the actual prefix and store root, treats reinstall as idempotent upgrade when the migration range matches, and preserves durable store state. `hideout package verify` validates extracted artifacts and installed prefixes; `hideout package uninstall` supports dry-run, package-owned file removal, unrelated-file preservation, durable-state preservation by default, and explicit `--purge` with survivor purge audit outside the deleted store. Gate 0 package smoke covers fresh install, missing helper/checksum fail-closed, upgrade preservation, incompatible migration denial, uninstall dry-run, preserve, and purge. Homebrew, signing, notarization, auto-update, Windows, public package managers, and enterprise deployment remain deferred. |
| Release hardening and compatibility matrix | Implemented. `hideout support matrix` exposes the Go-owned `hideout.support-matrix/v1` alpha support contract (`2026-07-alpha`): macOS arm64 first-class, Linux amd64/aarch64 supported with narrower smoke coverage, native degraded/development-only, DNS/HostFS/privilege claims gate-required, and required non-claims preserved. `hideout version` and `doctor` surface matrix status; `scripts/test-release-readiness.sh` writes redacted `hideout.release-readiness/v1` artifacts and keeps local-fast evidence distinct from release-candidate evidence. Gate 0 includes matrix schemas, docs drift checks, compatibility fixture smoke, and release-hardening smoke. |
| Profile templates and onboarding | Implemented. `hideout init` is template-aware and recommends `privacy` for first run. Built-ins are `privacy`, `hardened`, `dev`, and `debug`; non-interactive onboarding requires explicit profile/template/backend/network choices. `privacy` and `hardened` require `tun2socks`, a proxy secret ref, and a mediated resolver; `hardened` additionally requires enforced privilege separation on a non-native backend that can support product isolation evidence, or fails closed before profile creation unless the operator explicitly creates a visibly degraded fallback. Templates grant no HostFS rules and enable no adapter packs by default. Successful onboarding writes `profiles/<name>/onboarding-evidence.json` with redacted posture evidence; cancellation, missing choices, existing profile collisions, native-backend enforced hardened claims, and hardened degraded/unknown without explicit fallback write no success evidence. Gate 0 onboarding smoke covers the catalog, degraded honesty, evidence schema/redaction, and docs commands. |
| Workspace guard | Implemented before backend prepare; rejects host home, Hideout store, credential roots, and browser profile roots unless explicitly overridden. |
| Environment lifecycle | Unified named environments are implemented: every environment is named (explicit `env create` or deterministic auto-name per profile+workspace), carries a pinned base image declaration, and has identity fixed at creation (image declaration, backend config version, pinned workspace). `env create/list/inspect/recreate/remove`, `run --env <name>`, drift fail-closed with recreate hints, running-guest guards with `--force`, record-version bump with clean-and-recreate guidance (no migration), environment locking, SIGINT/SIGTERM cancellation, and runtime cleanup are implemented. MRU fingerprint selection and the top-level `list` command are removed. |
| Command Proxy And Command Adapters | Phase 1 product path implements registered `host.open` command shims using the `open-target-v1` argv schema. Default profiles register `open` and `xdg-open`; profiles may add more host-open command symbols through CLI or Manager/Web typed command-proxy plan/apply without adding new authority. 008 adds local, profile-scoped command capability adapters: digest-pinned JavaScript artifacts or the built-in root-sensitive adapter can own explicit command symbols and return strict Go-validated outcomes (`deny`, `simulate`, `rewriteGuest`, or non-applied `proposeCapability`). 011 adds a local adapter-pack lifecycle: operators can install local directories or exact-commit git sources into a store-wide registry, run deterministic pack tests, and explicitly enable one tested revision per profile with exact pack/revision/adapter/source-digest binding. Adapter enablement uses typed Manager Core plan/apply and CLI; broker routing fails closed on missing, changed, revoked, invalid, or undeclared-command/capability adapters. Root-sensitive adapter evidence remains command-name intent capture and is enriched by 009 privilege status; it does not claim absolute-path, syscall, setuid, or post-guest-root containment. |
| Adapter pack lifecycle | Implemented as a local lifecycle manager, not a public marketplace. `hideout adapter-pack` supports install, upgrade, list, inspect, test, enable, disable, and revoke; Manager `adapter-pack/*` routes manage the same digest-locked pack revisions. Core-owned schema/outcome/command/capability validation is the primary gate; pack-provided tests are mandatory before enablement but are only supporting evidence. Public publisher identity, signing, namespace protection, remote revocation, and marketplace trust remain out of scope until a public marketplace exists. |
| Host open | `host.open` supports external HTTP(S) URLs and workspace-mapped files through a brokered opener, isolated browser profile, local/private URL deny, DNS rebind checks, audit, and Gate 4 coverage. |
| HostFS Portal | `stat`, `read`, and `list` data plane is implemented for Linux guests through FUSE and broker RPC, with grants, reserved-store rejection, filtered list, and audit. Durable profile HostFS allow/deny rules are managed through the same lower-layer rule model from CLI and typed Manager/Web plan/apply. |
| HostFS write overlay | Implemented for explicit overlay grants. Write-class HostFS operations (`create`, `replace`, `append`, `truncate`, `mkdir`, `delete`, `rename`, `chmod`, constrained `chown`) stage durable session-local overlay records and return guest-visible success only after staging. Host lower files are unchanged until a local authenticated operator claims and applies a Manager decision through CLI/WebUI/TUI/API. Apply revalidates the base snapshot and fails closed on conflicts, stale claims, unsafe paths, or privilege-requiring chown; timeout/discard defaults deny and cleans staged content objects while preserving audit/decision evidence. It does not block workspace writes, provide DLP, contain a guest-root target, or claim to be the only host-mutation path when 009 privilege status is degraded/unknown. |
| Profile env policy | Durable `profile.env.public`, `profile.env.inherit`, and `profile.env.deny` are managed from CLI and typed Manager/Web plan/apply. Overview and API responses expose env names only, not public env values. |
| Network | `direct` and guest-side `tun2socks` modes are implemented. Proxy values are hidden from the target env. Privacy-mode DNS closure is implemented and validated on real Lima (Gate 3 passes): connected-subnet resolvers are blocked, the guest resolver is pointed at a guest-local DoH stub that forwards queries as DoH/HTTPS to the declared mediated resolver over the privacy path, and a connected-subnet-only environment is refused. A guest-root target can still rewrite routing/resolver config to restore a bypass (A3 non-claim). |
| Guest privilege separation and risk audit | Implemented for Lima. Hideout provisions a dual identity: target commands run as a non-root target user with target `sudo -n` and `/usr/bin/sudo -n` unavailable, while Go-owned privileged setup/cleanup for network and HostFS uses a separate root-control setup identity. Each run emits `guest.privilege.status` (`enforced`, `degraded`, or `unknown`) and `hideout.privileged_setup`/`hideout.privileged_cleanup` evidence; weak/pre-009 environments where target passwordless sudo still works are marked `degraded` with recreate/base-image guidance and no guest-root containment claim. Real Lima enforced and degraded proof modes are covered by `scripts/test-privilege-separation-smoke.sh`; Gate 3 also asserts `privilege_status=enforced` and `privileged_setup=network`. |
| Tool supply | Implemented as diagnostic-only `tools.expectedCommands` declarations. Hideout ships no package-installation providers, preset-based installers, guest-tool package storage, init/doctor materialization flags, or profile-tool install subcommands. Guest tools come from the declared base image plus operator-authored in-boundary setup run as an ordinary `hideout run`. |
| Manager API | Local token-protected API implements read-only overview resources, including reusable environments, plus typed `init/plan`, `init/apply`, `run/plan`, `run/apply`, `run/status`, command-proxy plan/apply, profile HostFS rule plan/apply, profile env plan/apply, evidence export plan/apply, operator decision/notice list/inspect/claim/resolve/ack, and reusable environment `stop`/`clean` plan/apply surfaces for TUI/WebUI. Init plans include structured next steps. It is not a raw profile writer, host execution API, or arbitrary VM control API. |
| TUI smoke surface | Implemented as the lightweight panel: `hideout tui` renders a capped persistent terminal dashboard from Manager overview and redacted audit data, with `--once` as the script/snapshot mode. Panel scope and planned interactions are defined in [tui-webui-experience.md](tui-webui-experience.md); tool panels show expected-command diagnostics. |
| WebUI smoke surface | Implemented as the fuller management surface over the Manager API: overview/audit summaries plus typed plan/apply operations. Scope is defined in [tui-webui-experience.md](tui-webui-experience.md); tool panels show expected-command diagnostics. It is not the final product UI. |
| Endpoint Exposure | Product `endpoint.expose.host-to-guest` is implemented for declared and run-scoped manual guest-loopback TCP candidates, with active owner validation, backend provider, audit, cleanup, and Boundary Summary. |
| Preview open | Minimal `preview.open` is implemented as the first consumer of host-to-guest exposure. Callback adapters, endpoint observation, and project-declared auto exposure are later/design-ready. |
| Boundary Summary | Default `hideout run` is quiet; `--verbose`, `explain`, `hideout audit show`, Manager API, TUI, or Web UI surfaces show redacted control-plane evidence. |
| Evidence redaction hygiene | Implemented. Generated machine-id is independent from displayed identity IDs, legacy coupled machine IDs rotate on profile load, and InitTask audit free-text fields pass through the shared deterministic control-plane redaction. |
| `hideoutd` daemon + live operations console | Implemented (local control plane and payload-driven live console). `hideout daemon start\|status\|stop` runs one per-user daemon per store, serving the existing typed Manager API by mounting the same handler over a store-rooted, guest-unreachable Unix socket (parity by construction; daemon status/event/background endpoints live outside `/api/v1/`). Every request is operator-token authenticated; unauthenticated refusals are recorded in a persistent, session-unbound daemon-local audit log without token material. It emits typed, redacted `liveconsole.Event` streams from real operation sources (environment stop/clean lifecycle, daemon-mediated run sessions, daemon background work, daemon audit tail, `evidence/export/apply`, and existing run session cleanup; no durable log; streams terminate on credential expiry), serves the WebUI over a tokened loopback transport whose panels seed once and then apply event payloads via `EventSource`, and feeds the TUI through `daemon.SubscribeEvents` with the same reducer model. Healthy streams do not perform steady-state overview/audit polling; daemon-less or closed streams fall back to prior behavior. Deterministic JavaScript reducer proof tests and `scripts/test-live-console-smoke.sh` cover schema drift, no-polling handlers, TUI terminal proof, stream health, backpressure, multi-subscriber sequence consistency, production emit sources, and redaction scans. Existing typed environment stop/clean apply can run as background work through `POST /daemon/background` with queryable status and bounded fail-closed shutdown. After restart it fails closed for live resources it cannot prove it owns (report + audit, never re-adopt or destroy). Daemon absence leaves every embedded surface unchanged. Prompt channels are out of scope. |
| Export/share redaction boundary | Implemented. `hideout audit export` produces a local shareable artifact from an audit slice, release-evidence bundle, Boundary Summary, or explicitly selected doctor report. Every exported artifact reasserts the Go-owned control-plane strip, resolves referenced local evidence inline or refuses, applies configured `audit.redact` user-data policy with export semantics, preserves the fixed evidentiary set by failing closed on attempted redaction/mutation, writes no partial artifact on failure, emits a local meta-audit summary, and validates through `schemas/export-artifact.schema.json` plus `scripts/test-export-redaction-smoke.sh`. |
| Doctor diagnostics and recovery | Implemented. `hideout doctor` emits the existing local readiness checks as human output or a structured `hideout.doctor-report/v1` JSON report, supports explicit level/feature selectors for local inventory/status diagnostics without treating local checks as release-gate evidence, writes redacted `--evidence-out` reports on request, and lets operators export those reports only through explicit `--source doctor-report --doctor-report <path>` selection. `doctor --fix --dry-run` previews safe InitTask repairs and `doctor --fix --apply` applies only typed safe repairs with init audit evidence; unsafe recovery remains guidance. Gate 0 now includes `schemas/doctor-report.schema.json` and `scripts/test-doctor-smoke.sh` for human/JSON, required failure, warning exit semantics, feature-scope diagnostics, evidence redaction, doctor-report export, and dry-run recovery. |
| Operator decision center | Implemented. Actionable decisions (`hostfs.write`, promoted-provider `adapter.proposal` when such a provider exists, and `evidence.share`) are separate from informational notices (`privilege.status`, `background.status`). Decisions use claim/lease/timeout/default-deny semantics and Manager-owned provider dispatch; notices only broadcast and acknowledge facts. Existing HostFS write routes are compatibility shims over the generic decision store, pure local `hideout audit export` remains synchronous, and `hideout audit export --share` creates an `evidence.share` decision whose approval releases the artifact after export redaction checks. CLI (`hideout decision ...`, `hideout notice ...`), Manager API, WebUI, TUI, and daemon events expose redacted records without claim tokens or provider-private refs. Covered by `schemas/decision-record.schema.json`, `schemas/notice-record.schema.json`, and `scripts/test-decision-center-smoke.sh`. |
| Script runtime | Required Phase 1 supports `command.decide`, `audit.redact`, and 008 command adapter entrypoints through constrained goja ABIs with deterministic time/randomness. `decideCommand(ctx)` continues to govern existing command policy, `redactAudit(ctx)` governs export/user redaction, and `decideCommandAdapter(ctx)` can classify command-name intent and return strict Go-validated adapter outcomes. Bounded context query APIs beyond the supplied command facts are still later work. |

## Not Yet Productized

| Area | Status |
| --- | --- |
| Generic tool provider declarations | Dropped as a product direction: Hideout ships no package-installation providers; tool declarations are thin expected-command diagnostic records. The declarative guest base-environment artifact class (base image references; guest domain, shareable through the ecosystem) is the accepted direction. Imperative environment recipes remain out of scope. |
| `endpoint.expose.guest-to-host` | Lab/separate design. Required before adb, browser DevTools, host service reachability, or similar workflows. |
| Endpoint observe / AccessSensor | Later. Observation may produce audit and warnings, but must not authorize exposure by itself. |
| Browser control | Lab/separate design. |
| adb / device / simulator workflows | Adapter recipes over future guest-to-host and OpenTarget capabilities; not productized. |
| Host app/resource provider recipes | Design-ready. Core must supply facts and validators; adapters own product risk logic. |
| Public ecosystem | Later. Trust MVP is two-tier: local artifacts, and third-party artifacts behind digest pinning, a permission diff, and one explicit confirmation. Marketplace day-1: signing, revocation/kill-switch, publisher identity, and namespace protection — designed when the marketplace launches, not before. |
